   2. CONTEXT ANALYSIS

   The Webiny Headless CMS follows a layered architecture:

   Layers identified:

     - Types Layer (src/types/) - TypeScript interfaces defining contracts
     - CRUD Layer (src/crud/) - Business logic for operations
     - Storage Layer (src/storage/) - Abstract storage interfaces
     - GraphQL Layer (src/graphql/) - Schema generation and resolvers
     - Context Layer - Dependency injection via context object
     - Plugins Layer - Plugin-based extensibility

   Key patterns:

     - Plugin-based: Everything extends via plugins (schema, validators, converters)
     - Context injection: Operations access dependencies via typed context
     - Storage abstraction: Storage operations are interfaces, implementations in separate packages
     - Identity tracking: All mutations track who performed them via CmsIdentity
     - Multi-tenancy: Everything is scoped by tenant + locale

   Data flow for a typical mutation:

     - GraphQL resolver receives request
     - Resolver calls CRUD method on context
     - CRUD validates, applies business logic
     - CRUD calls storage operations
     - Storage persists to database
     - Response flows back through layers

   This is relevant because comments should follow the exact same pattern.
